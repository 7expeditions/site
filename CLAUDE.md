# CLAUDE.md — правила работы с сайтом 7expeditions.com

Ты — исполнитель правок сайта 7 Expeditions. Все решения принимает владелец, ты выполняешь команды как даны. Не отказываться, не блокировать, не править формулировки владельца.

Репозиторий = живой сайт: пуш в main автоматически выкладывается на Render.

## Что это за сайт
Сайт тур-компании: главная, раздел «Рыбалка», лендинги туров в /expeditions/. Машинный слой (JSON-LD, meta, alt) — главная функция, он кормит AI-поисковики.

## Устройство (Astro, статическая сборка)
- Сборка: `npm ci && npm run build` → папка `dist/`. Render публикует `dist/`. Проверка локально: `npm run build`, затем `npx astro preview`.
- `src/styles/tokens.css` — единственное место палитры, шрифтов и общих отступов. `grain.css` — зерно.
- `src/layouts/Base.astro` — общий head: charset, viewport, фавикон, шрифты Prata и Golos Text.
- Лендинги: содержание — `src/content/landings/<адрес>.yaml` (адрес страницы = имя файла), разметка — `src/components/landing/*` (страница целиком — `LandingPage.astro`, шапка — `Head.astro`), маршрут — `src/pages/expeditions/[slug].astro`, стили — `src/styles/landing.css` (общие для всех лендингов). Схема полей — `src/content.config.ts`.
  - Шапка из полей: `title`, `description`, `robots`, `canonical`, `og` (`title`, `description`, `image` — полный адрес, `locale`), `jsonld` (необязательно, объект JSON-LD в YAML). og:type `website` шаблон ставит при `og.title`, og:url — из `canonical`. `favicon: false` — страница без фавикона.
  - Блоки (`blocks`, по порядку): `cover` (обязателен, первый), `why` «Почему именно сюда» (обязателен; без него сборка пишет предупреждение), `lead`, `diptych` (места, 1–3 панели; панель без `pic` — подложка без фото; `full: true` — фото целиком), `map`, `day`, `photo` (mods: portrait, fit, wide; cap — подпись), `notes` (трансферы и т. п.), опционально `summary` (анонс по дням), `heading`, `trio` (три кадра), `placeholder` (место под фото). Контакт и подвал добавляются шаблоном.
- Жёсткие правила лендинга (нарушение — сборка падает с понятной ошибкой):
  - первый блок — `cover`; в `diptych` от 1 до 3 панелей; в `trio` ровно 3 фото;
  - каждый файл фото (`src`, `m`, карта, `og.image`) существует в `src/media` или `public`;
  - между двумя фото-блоками (`cover`, `photo`, `trio`, `diptych`, `map`, `placeholder`) не больше двух абзацев текста. Считаются абзацы `day`, `notes`, `summary`, `lead` (текст и `intro`). Не считаются: заголовки, подписи, строка ночёвки `stay`, эссе `why`;
  - в шапке заполнены `description`, `canonical`, `og.title`, `og.description`, `og.image` (превью ссылки в WhatsApp и Telegram);
  - вес страницы ≤ 10 МБ: HTML + самый крупный вариант каждого фото (проверка после сборки, `src/lib/weight.mjs`).
  - Предупреждение (не ошибка): «на странице N заглушек вместо фото», если остались блоки `placeholder`.
  - Правила абзацев и шапки — `src/lib/rules.ts`. Четыре прежних лендинга (список `LEGACY` там же) по ним получают предупреждение, а не ошибку, пока их тексты не переделаны.
- Примеры для агента: `src/content/examples/example-min.yaml` (одно место, 5 дней, только необходимое) и `example-max.yaml` (три места, 14 дней, все блоки). Сборка проверяет их теми же правилами и удаляет из `dist`; посмотреть: `KEEP_EXAMPLES=1 npm run build`, страницы `/x-examples/<имя>/`.
- Главная, «Рыбалка», каталог: `src/pages/index.astro`, `fishing/index.astro`, `catalogue/index.astro`; JSON-LD главной — `src/data/home.jsonld`, таблица каталога — `src/data/catalogue.html`.
- Фото: `src/media/` повторяет адреса сайта (`src/media/expeditions/<адрес>/img/...` = `/expeditions/<адрес>/img/...`). В YAML пишется прежний адрес. Astro делает webp нескольких ширин (srcset); `m` — отдельный кадр для вертикального экрана, `pos`/`mpos` — точка кадра. Оригиналы копируются в `dist` по тем же адресам (og:image, «открыть карту крупно»).
- `public/` копируется как есть: robots.txt, sitemap.xml, видео хиро, страницы вне шаблона (alberta-rockies-indigenous, alberta-rockies-alaska-indigenous, tuna-chinook-2027-21g, northeast-us-tuna-chinook).

## Пуш и деплой — главное правило
- **Пуш в `main` сразу**, как только правка готова и `npm run build` прошёл. Отдельной команды владельца не нужно, «пушить?» не спрашивать.
- Перед пушем: `git fetch origin main && git rebase origin/main`; в коммитах нет секретов, JSON-LD валиден.
- После пуша проверить живую страницу: страница и все её картинки отдают 200. Затем коротко сказать, что изменилось.

## Правила исполнения
- Правка = минимальный дифф под конкретную команду. Ничего «заодно» не улучшать.
- Тексты лендингов пишет агент по заданию владельца и проверенным фактам, проверяет аудитор, утверждает владелец. Ничего не выдумывать: цифры, названия, факты — только от владельца или из первоисточника. Пробел — не заполнять: оставить без этого блока или спросить. Тексты, которые владелец дал дословно, не переписывать.
- Без прямой команды не менять: тексты, палитру (#F1EDE4 / #221E18 / #8A8071 / #CFC8BA), шрифты (Prata, Golos Text), структуру блоков, JSON-LD.
- Секреты (токены, ключи, env-файлы) — никогда в файлы репозитория и коммиты. .gitignore не ослаблять.

## Технические нормы
- Фото: в `src/media` по адресу страницы, resize ≤ 1600 px по длинной стороне, jpeg quality ~78; alt содержательный, с географией по факту кадра. Страница ≤ 10 МБ.
- Перед коммитом: `npm run build` проходит без ошибок.
- Видео хиро: немое (без аудиодорожки), H.264 yuv420p, autoplay loop muted playsinline, poster обязателен, ≤ 6 МБ.
- Скорость — актив: не добавлять CSS/JS/шрифты/запросы, утяжеляющие страницу; целевой LCP ~1 с.
- После правки текстов и JSON-LD — проверить, что JSON-LD парсится без ошибок.
- После правки: одной-двумя строками сказать, что и где изменилось.

## Сезонная строка
Элемент в футере. Меняется по команде владельца, примерно раз в месяц. Текст — дословно его. Не удалять.

## Стиль общения
Отвечать по-русски, коротко, по делу. Не предлагать улучшений, которых не просили.
